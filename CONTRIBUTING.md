# Contributing to the Backend foundation

## Required baseline

- Java 21 LTS
- Spring Boot 4.1.2 dependency baseline
- Gradle 9.8.2 through the Gradle Wrapper
- Architecture revision `NESHANE-V3-ARCH-P00-005`

Do not add Business Service code to `architecture-fixtures/`. Those projects exist only to make the dependency-direction checks non-vacuous.

## Wrapper integrity gate

The repository tracks `gradlew`, `gradlew.bat`, and `gradle/wrapper/gradle-wrapper.jar` generated by the approved Gradle 9.8.2 distribution.

The approved evidence is:

- Distribution URL: `https://services.gradle.org/distributions/gradle-9.8.2-bin.zip`
- Distribution SHA-256: `21bd5da2de49b642904077f38c0efdc7778e92b3ed0889392dca61b97e389607`
- Wrapper JAR SHA-256: `3b8a25775a69158b5ad2b1d17a80a88dc7b40a352a73eb27d06c612a7ce68e98`

The tracked Wrapper JAR was verified against the approved SHA-256. Regenerate it only with an independently verified Gradle 9.8.2 distribution, and verify the resulting bytes before accepting any replacement. Do not copy or hand-author Wrapper scripts or the JAR.

PowerShell verification after generation:

```powershell
Get-FileHash -Algorithm SHA256 .\gradle\wrapper\gradle-wrapper.jar
Select-String -Path .\gradle\wrapper\gradle-wrapper.properties -Pattern 'distributionUrl|distributionSha256Sum'
```

The JAR hash must match the approved value above. The distribution URL and `distributionSha256Sum` must match `gradle-wrapper.properties`.

## Manual verification commands

After network/dependency execution is authorized:

```powershell
.\gradlew.bat --version
.\gradlew.bat clean build
.\gradlew.bat dependencies
.\gradlew.bat check
```

Useful module-scoped checks:

```powershell
.\gradlew.bat :architecture-fixtures:domain:build
.\gradlew.bat :architecture-fixtures:application:build
.\gradlew.bat :architecture-fixtures:adapter:build
.\gradlew.bat verifyArchitectureBoundaries --offline
.\gradlew.bat :architecture-tests:test verifyArchitectureBoundaryFixtures --offline
```

The root `check` task includes formatting, project-graph boundary verification, policy fixtures and ArchUnit
tests through `verifyArchitectureBoundaries`. No execution result is implied by this document.

Dependency locking is enabled for all Java projects. Generate or update lockfiles only in an authorized dependency-resolving task and review every resulting version change before commit.

## Dependency rules

- Domain has no project dependency and no Spring/Hibernate/JPA dependency.
- Application may depend on Domain.
- Adapter may depend on Application and obtains Domain transitively.
- Cycles, stale/missing policy registration, unauthorized direct/transitive project dependencies and service
  API exposure of project dependencies fail `verifyModuleBoundaries`.
- Business Services must remain independently buildable and may not depend on another service's implementation.
- ArchUnit rejects protected Domain/Application direction violations, cross-service implementation imports and
  Platform-to-Service imports; protected production scopes must not be empty.
